## 二、游戏内灵敏度参数体系（玩家实测帖归纳，最重要的一节）

该手游灵敏度是 **"滑屏 / 开火 / 陀螺仪" 三套并行体系，各自按武器 + 开镜档位细分**，不是端游单一全局灵敏度。参数集合如下：

**基础开关**
- 镜头转向模式（固定速度 / ?）
- 转向辅助（开/关）
- 陀螺仪开关（开/关，老机型可能不支持）——设置路径：设置 → 操作设置 → 陀螺仪开关
- 陀螺仪辅助瞄准（存在该机制，用于跟枪）

**滑屏灵敏度**：转向灵敏度、腰射开火、冲锋枪开镜、步枪开镜、机枪开镜、狙击枪开镜、冥驹(狙击枪)二段开镜、金牌猎头开镜…
**开火灵敏度**：腰射开火、各武器开镜开火、冥驹二段开镜开火…
**陀螺仪灵敏度**：垂直灵敏度、转向灵敏度、冲锋枪开镜、步枪开镜、机枪开镜、狙击枪开镜、冥驹二段开镜…

来源：7724 实测帖（http://m.7724.com/syzx/news/194865.html）、九游"陀螺仪在哪打开"（9game.cn/wwqyynxd1/11608366.html）、3DM/游侠攻略（提到陀螺仪辅助瞄准、"按钮转动视角"开关）。具体滑块范围（如 0~200 或百分比）**未获官方出处**，需真机/截图核实。

**产品含义**：数据模型必须以"武器 × 开镜档位 × {滑屏/开火/陀螺仪}"设计；滑块范围等 UI 细节要在有真机时从游戏内设置页截图校准。

## 四、"自动调校"的可选技术路线与合规红线

| 路线 | 做法 | 优点 | 风险 |
|---|---|---|---|
| A. 预设方案库 | 内置职业/高手数值包，按玩家风格推荐 | 零风险、最快落地 | 非"自动" |
| B. 测试-推荐引擎 | App 内做"滑屏/跟枪测试"，量化玩家手部习惯 → 算法换算推荐值 | 个性化、不动游戏 | 需设计有效测试 |
| C. 陀螺仪实测标定 | 利用 Android SensorManager（TYPE_GYROSCOPE 等，公开 API）测量玩家真实握持/转动手感基线 → 推荐陀螺仪灵敏度 | 有硬件数据支撑 | 需真机校验 |
| D. 云端数值/攻略导入 | 生成灵敏度配置二维码/文本，玩家手动填入游戏 | 低风险 | 无法跨游戏直接注入 |

**合规红线（务必遵守）**：
- 本游戏为腾讯发行，接 ACE 反作弊体系。**任何向游戏进程注入模拟触控/读取内存/修改配置（无障碍模拟点击、MotionEvent 注入、Root 注入、压枪宏）均属外挂/宏，极大概率违规封号**（条款原文未抓到，属高置信推断）。
- **安全的边界 = 离线测试 + 数值计算/推荐 + 玩家手动填入游戏**。我们只做"测量-推荐-教程引导"，绝不触碰游戏进程与输入。
- 我方案中需要玩家手动在设置里输入数值，或提供"引导截图+数值表"，这是合规且用户可接受的形态。

**推荐路线**：A（预设库，起步最快）→ 叠加 B（自研"手部校准测试"给出个性化推荐，核心差异化）→ 按需加 C 辅助（陀螺仪档位，用户可选开启"陀螺仪一起调"，正好对应你的需求点）。

## 五、开发方案建议（技术选型与范围）

### 5.1 平台与技术栈

- **首发 Android（原生 Kotlin + Jetpack Compose，或 Flutter）**：
  - 理由：用户持有安卓机即可真机调测；安卓对传感器（陀螺仪）、无障碍辅助（仅做教程悬浮窗/复制数值，不做点击注入）支持完整。
  - 若后续要 iOS：传感器 API 对称，代码可移植（Flutter 双端更省，但陀螺仪采样与 UI 性能原生更可控；**建议：若做"真机滑屏/陀螺仪测量"，优先原生 Kotlin 单端起步，验证核心算法后再考虑跨端**）。
- **为何不做纯网页**：网页无法读陀螺仪（需要 Web 传感器 API 且权限差）、无法给出真正"自动/校准"体验；但**可以先做一个"灵敏度计算器 + 推荐码生成"的 MVP 网页验证需求**，成本最低（参见里程碑）。

### 5.2 功能范围（建议 MVP → 迭代）

**MVP（第 1 版，验证核心价值）**
1. 滑屏灵敏度设置浏览与预设推荐（内置"低/中/高/职业"几套方案，按主武器分类）
2. 引导页：把每个参数显示名与"在设置里哪个位置"对应（配截图占位/文字路径）
3. 数值"一键复制成清单"，用户照着填进游戏设置

**第 2 版（核心差异化：个性化自动调校）**
4. **手指滑屏校准测试**：App 内横屏画布，用户以自然习惯速度滑屏 N 次，记录滑动的**位移-速度分布**（用户手速基线）
5. **陀螺仪校准测试**（用户可选开关）：用陀螺仪采样记录用户转动手机的**幅度/速度/稳定度**基线
6. 依据基线 + 用户自评（喜欢快跟枪/稳架枪）→ 推荐一组"滑屏 + 开火 + 陀螺仪（如启用）"数值，并解释理由
7. 保存多套个人预设，可对比、可回滚

**第 3 版（生态/增强，可选）**
8. 灵敏度分享码（文本/二维码导入导出）
9. 武器类型 × 地图场景的专项建议（架枪 vs 近战扫射）
10. 新手引导：陀螺仪到底开不开——用校准数据给出个性化建议

### 5.3 关键技术点（第 2 版算法构思）

- **滑屏基线**：Android `View`/Compose 手势回调记录 `MotionEvent`（down→move→up），算出每次滑动的距离 px、耗时 ms、峰值速度；做多次采样得分布 → 归一化为"玩家手速档位"。
- **陀螺仪基线**：`SensorManager.TYPE_GYROSCOPE`（或 `TYPE_ROTATION_VECTOR` 更稳），让用户做"匀速转 90°""快速甩视角"等动作，积分或采样角速度统计 → 得到"玩家转动习惯档位"。
- **推荐映射**：档位 × 风格 → 对应预设数值区间（先用 A 方案的数据做锚点，规则可调），后续可收集用户反馈微调。
- **校验**：真机上把推荐值填入游戏 → 训练场打靶体验 → App 内"好不好用"反馈闭环（版本 2 后期）。

### 5.4 需要用户在开发前回答 / 准备的事项

1. 目标平台：先做安卓？还是要求 iOS 同步？（决定技术栈：原生 Kotlin vs Flutter）
2. 你要"帮玩家全自动改游戏设置"，还是"测量+推荐数值，玩家手动填"？（我强烈建议后者——合规红线；前者技术上能做但等于做外挂，会封号且违反平台规则）
3. 是否有真机（安卓）可做真机调试与陀螺仪验证？（本机当前无 Android SDK/模拟器，纯开发机。开发调试需要：安装 Android Studio + SDK；或连接一台开了 USB 调试的安卓真机；或装模拟器——但**模拟器没有真实陀螺仪**，陀螺仪相关功能必须在真机验证）
4. 名字/品牌：是否需要应用上架（需要开发者账号、软著等），还是先本地自用/小范围分发？
